# TECH_STACK — EXCELSIO 2.0

**Статус:** предложение (Этап 1). Версии зафиксируем на Этапе 2 при `npm install` — в этом документе указаны актуальные на момент написания линии, а не точные пины.
**Связанные документы:** `ARCHITECTURE.md`, `DECISIONS.md`, `SECURITY.md`.

---

## 1. Требования к стеку (из которых делался выбор)

1. Mobile-first, премиальные анимации, но предсказуемый FPS на средних Android.
2. Собственная админка: CRUD проектов/фотографий, загрузка изображений, заявки — значит, нужен сервер и БД.
3. SEO и корректные превью в Telegram — нужны серверные метаданные.
4. Долгая поддержка одним человеком: минимум магии, типы, понятная структура.
5. Невысокая стоимость хостинга (персональный проект, не стартап).
6. Возможность масштабирования без переписывания (мультиязычность, больше контента, CDN).

## 3. Сравнение архитектурных вариантов

| Вариант | Плюсы | Минусы | Вердикт |
| --- | --- | --- | --- |
| **A. Модульный монолит: Fastify + SSR React (Vite) + PostgreSQL** | Один деплой; SSR/SEO из коробки; полный контроль; общие типы; умеренная сложность | Нужен VPS и знание SSR-режима Vite; чуть больше кода, чем у фреймворка «из коробки» | **Рекомендуется** |
| **B. SPA (CSR) + Fastify API** | Проще всего стартовать; деплой как статика + API | Плохие OG-превью и SEO для кейсов; нужен пререндер или edge-функции; пустой первый экран на медленном телефоне | Допустим как упрощение, но противоречит REQUIREMENTS (SEO-7) |
| **C. Next.js (App Router) fullstack** | SSR/ISR, метаданные, картинки из коробки; огромная экосистема | Свой рантайм и абстракции; сложнее деплой без Vercel; больше «магии» при поддержке одним человеком; предпочтение проекта — Vite | Хорошая альтернатива, если важнее скорость старта, чем контроль |
| **D. Astro (SSG/SSR) + React-острова** | Отличный статический перформанс; минимум JS | Админка как остров — не типичный сценарий; два мышления в проекте | Не рекомендуется для 2.0 |
| **E. Headless CMS (Payload/Strapi/Directus) + React** | Админка и загрузки почти бесплатно | Ещё один сервис и своя БД; кастомизация всегда «через плагины»; полный контроль SEO-метаданных — отдельная работа | Не рекомендуется: REQUIREMENTS требуют собственной админки |
| **F. BaaS (Supabase/Firebase) + React** | Быстро: auth, storage, БД, realtime | Вендор-лок, стоимость при росте, ограничения на обработку изображений, приватность заявок, `.ru`-аудитория | Не рекомендуется для основного пути |

## 4. Хранилище изображений

| Вариант | Плюсы | Минусы | Когда выбирать |
| --- | --- | --- | --- |
| **S3-совместимое хранилище** (Yandex Object Storage, VK Cloud, Selectel, Cloudflare R2) | Дёшево за объём, CDN, бэкап вне сервера, не влияет на диск VPS | Внешняя зависимость, нужна настройка CORS/публичного доступа, оплата | **Рекомендуется** при росте галереи (≥ 1–2 ГБ) |
| **Локальный том + раздача через Caddy** | Ноль зависимостей, простая отладка, бесплатно | Привязано к серверу, бэкап медиа обязателен, нет CDN | Рекомендуется на старте (пилот, Этапы 5–9) |
| **Хранилище в БД** (`bytea`) | Один бэкап | Раздувает БД, плохой кэш, дороже по памяти | Никогда |

**Решение:** интерфейс `StorageAdapter` с двумя реализациями (`local`, `s3`); выбор — через переменную окружения. Стартуем с `local`, переключаемся без изменения кода.

## 5. Хостинг и стоимость (ориентировочно, требует проверки на дату выбора)

| Компонент | Вариант | Ориентировочная цена | Комментарий |
| --- | --- | --- | --- |
| Домен `.ru` | Регистратор (например, reg.ru / timeweb) | ~200–400 ₽/год | Продление ежегодно; владелец подтверждает, где домен |
| VPS | 1–2 vCPU, 2–4 ГБ RAM, 20–40 ГБ SSD | ~300–900 ₽/мес | Достаточно для сайта + PostgreSQL; легенда «начни с малого» |
| Хранилище медиа | локальный диск на старте | 0 ₽ | До ~5 ГБ разумно держать локально |
| S3 + CDN (позже) | 10–50 ГБ | ~50–300 ₽/мес | Оплата по факту |
| Резервные копии | отдельный бакет/сервер | ~50–150 ₽/мес | Обязательно |
| E-mail (SMTP) | транзакционный провайдер | 0–500 ₽/мес | Резервный канал; Telegram бесплатен |
| TLS | Caddy + Let's Encrypt | 0 ₽ | Автоматически |
| CI | GitHub Actions (public repo) | 0 ₽ | Лимиты бесплатного тарифа достаточны |

Итого на старте: **ориентировочно 400–1200 ₽/мес**. Точные цены и условия оплаты утверждаются перед Этапом 11 (деплой). Альтернатива без VPS — статический хостинг + serverless API, но тогда теряется простота единого деплоя и SSR.

## 6. Политика зависимостей

1. Перед добавлением пакета — проверить: есть ли решение стандартными средствами, размер, активность поддержки, лицензия, число транзитивных зависимостей.
2. Каждый новый рантайм-пакет фиксируется в этом документе строкой «зачем».
3. Размер бандла проверяется на каждом этапе (`npm run build` → отчёт по чанкам); регресс > 20 KB gzip на публичном маршруте требует обоснования.
4. Только `npm` (lock-файл `package-lock.json` коммитится). Никаких «плавающих» `^`-версий в продакшн-зависимостях без нужды: обновления — отдельными коммитами.
5. Аудит: `npm audit` перед релизом; критические уязвимости закрываются в течение 7 дней.

## 7. Что НЕ используется и почему

| Технология | Причина отказа |
| --- | --- |
| Tailwind CSS | Противоречит выбранной дизайн-системе на CSS-переменных и BEM/SCSS |
| UI-киты (MUI, Ant, Chakra) | Ломают уникальный визуальный язык, тяжелы для мобильных |
| GSAP / Lottie / Three.js | Избыточный вес и сложность для задачи; Motion + CSS хватает |
| GraphQL | Нет потребителей, кроме одного фронтенда; REST проще |
| WebSocket/SSE | Не требуется в 2.0 |
| Redis | Не нужен при одном инстансе (кэш в памяти); подключать при горизонтальном масштабировании |
| Kubernetes | Несоразмерно задаче |
| Docker Swarm / несколько сервисов | Один Compose-файл на 3 контейнера достаточно |
| Существующий FontAwesome CDN | Заменяется локальными SVG-иконками (в `src/icon/` уже есть основа) |

## 8. Итог: рекомендуемая конфигурация

- **Node.js 22 LTS**, **TypeScript 5 strict**, **React 19**, **Vite 7**, **SCSS**, **Motion 14**, **React Router 7**, **Zod**, **TanStack Query** (только админка), **react-hook-form**.
- **Fastify 5** + **Drizzle ORM** + **PostgreSQL 16+** + **sharp** + **argon2** + **pino**.
- **npm workspaces**: `apps/web`, `apps/api`, `packages/shared`.
- **Деплой:** один VPS, Docker Compose (app, postgres, caddy), GitHub Actions CI.
- **Старт медиа:** локальный том → позже S3-совместимое хранилище без изменения кода.

Требует утверждения владельцем (см. `DECISIONS.md`): SSR vs SPA, PostgreSQL vs SQLite, локальный диск vs S3, e-mail-провайдер, хостинг.
