# REQUIREMENTS — EXCELSIO 2.0

**Статус документа:** черновик требований версии 2.0. Утверждается владельцем проекта.
**Связанные документы:** `ARCHITECTURE.md`, `TECH_STACK.md`, `DESIGN_SYSTEM.md`, `SECURITY.md`, `ROADMAP.md`.

Обозначения приоритетов: **M** — must have (входит в релиз 2.0), **S** — should have (желательно, если не растягивает этап), **C** — could have (после релиза), **W** — won't have (явно вне границ 2.0).

---

## 1. Назначение и аудитория

**Назначение.** Личный сайт-портфолио веб-разработчика и фотографа: показывает коммерческие и личные веб-проекты, авторскую фотографию, позволяет связаться с автором и получать заявки.

**Аудитории:**

1. **Потенциальный заказчик разработки** — пришёл по ссылке из Telegram/резюме, за 30–60 секунд должен понять уровень и найти контакт.
2. **Заказчик съёмки / ценитель фотографии** — пришёл за галереей, смотрит с телефона, часто с мобильного интернета.
3. **Коллеги, HR, рекрутеры** — изучают кейсы, стек, подход.
4. **Владелец (администратор)** — управляет контентом через собственный `/admin` без правки кода.

**Ключевой сценарий.** Пользователь открывает главную на телефоне (360–400 px), видит визуально сильный первый экран, листает подборку проектов и фотографий, открывает кейс, затем пишет через контактную форму или Telegram.

## 2. Границы версии 2.0

### Входит в 2.0

- Публичные страницы: Home, Development, Project Details, Photography, About, Contact.
- Собственная админка: проекты, фотографии, категории, заявки, базовая настройка сайта.
- Авторизация администратора (логин/пароль, серверная сессия).
- Загрузка и автоматическая оптимизация изображений (ресайз, форматы, плейсхолдеры, вырезание EXIF).
- Контактная форма с сохранением заявок в БД и уведомлением владельца.
- SEO-база: метаданные по страницам, Open Graph, `sitemap.xml`, `robots.txt`, JSON-LD, человекочитаемые URL.
- Адаптивность mobile-first, доступность (a11y), поддержка `prefers-reduced-motion`.
- Деплой на собственный домен с HTTPS, резервные копии, базовая наблюдаемость.

### НЕ входит в 2.0 (явно)

- **W** Регистрация посетителей, личные кабинеты, комментарии, лайки, подписки, соцсеть.
- **W** Мультиязычность интерфейса (архитектура готова к добавлению, но в 2.0 только русский; допустимы английские термины в кейсах).
- **W** Интернет-магазин, продажа фотографий, оплата.
- **W** Мобильные приложения, PWA-офлайн (можно рассмотреть после релиза).
- **W** Микросервисы, Kubernetes, отдельная headless CMS, GraphQL.
- **W** Публичный REST API для третьих сторон.
- **W** Командная работа в админке (роли кроме `admin`).

## 5. Критерии приёмки релиза 2.0

1. Все страницы из раздела 3 доступны публично, заполняются из админки без правки кода.
2. Администратор может войти, создать проект и загрузить фотографии с телефона; изменения появляются на сайте без пересборки.
3. Контактная форма сохраняет заявку и присылает уведомление в Telegram.
4. `sitemap.xml`, `robots.txt`, OG-теги и JSON-LD корректны; страницы кейсов отдают HTML с метаданными (проверка через `curl` и валидатор).
5. Lighthouse mobile ≥ 90 (Performance), 100 (Accessibility, SEO/ Best Practices) на Home, Photography, Project Details.
6. На 360 px нет горизонтального скролла, все тач-цели ≥ 44 px.
7. Сайт работает по HTTPS на `excelsio-moments.ru`, есть резервная копия и инструкция восстановления.
8. `npm run typecheck`, `npm run lint`, `npm run build`, тесты — проходят на `main`.

## 6. Открытые вопросы (требуют решения владельца)

1. Язык контента: только русский или двуязычный сайт (RU + EN)? В 2.0 заложен только русский, но контент-модель готова к переводу.
2. Нужны ли отдельные публичные страницы для отдельной фотографии (`/photography/:slug`) или достаточно лайтбокса?
3. Бюджет хостинга в месяц (влияет на выбор PostgreSQL vs SQLite и S3 vs локальный диск).
4. Кому принадлежит домен `excelsio-moments.ru` и где он зарегистрирован (для настройки DNS на Этапе 11).
5. Судьба первой версии сайта: перенести в `legacy/v1/` и оставить как архив, либо заменить окончательно?
6. Нужна ли политика конфиденциальности как отдельная страница (рекомендуется — да, из-за формы).
