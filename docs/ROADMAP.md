## Этап 1 — Архитектура и документация 🚧

**Результат:**

- `docs/REQUIREMENTS.md`, `ARCHITECTURE.md`, `TECH_STACK.md`, `DESIGN_SYSTEM.md`, `ROADMAP.md`, `SECURITY.md`, `DECISIONS.md`.
- `.gitignore` под React/Vite/TS/Node.

**Критерии готовности:**

- [x] Все документы созданы и не противоречат друг другу.
- [x] Зафиксированы решения, требующие утверждения владельцем (`DECISIONS.md`, раздел «Открытые вопросы»).
- [x] Правила из ТЗ перенесены в `AGENTS.md` дословно.
- [x] `.gitignore` покрывает `node_modules`, артефакты сборки, `.env`, ключи, локальные данные.
- [ ] Коммит `chore: initialize excelsio architecture and documentation` (выполняет владелец или агент с shell-доступом).

**Проверки:** проверка типов/линтер/сборка неприменимы (кода приложения ещё нет). Проверено: состав файлов, отсутствие секретов, соответствие правилам ТЗ.

## Этап 2 — Scaffold проекта (frontend) ⏸

**Цель:** работающий каркас приложения и дизайн-системы без бизнес-логики.

**Результат:**

1. Монорепозиторий: `apps/web`, `apps/api`, `packages/shared` (npm workspaces), `tsconfig.base.json`.
2. `apps/web`: Vite 7 + React 19 + TypeScript strict + SCSS, `entry-client`/`entry-server`, ESLint + Prettier.
3. `styles/tokens.css` со всеми токенами из `DESIGN_SYSTEM.md`; `reset`, `base`, миксины.
4. Каркас роутинга (Home, Development, Photography, About, Contact, 404), `CapsuleNav`, `Footer`, layout-обёртка.
5. Перенос v1: `src/` → `legacy/v1/` **отдельным коммитом**, только после подтверждения (D-009).
6. Скрипты: `dev`, `build`, `typecheck`, `lint`, `format`.
7. Решение по SSR-режиму Vite (D-001) зафиксировано в `DECISIONS.md`.

**Критерии готовности:**

- [ ] `npm install` выполняется без ошибок и предупреждений об уязвимостях критического уровня.
- [ ] `npm run dev` поднимает приложение; главная отдаёт HTML.
- [ ] `npm run build` завершается успешно; отчёт по размеру бандла приложен.
- [ ] `npm run typecheck` и `npm run lint` — 0 ошибок.
- [ ] На 360×640 нет горизонтального скролла; капсульная навигация доступна с клавиатуры.
- [ ] Токены используются во всех стилях (проверка `grep` на hex-коды в компонентах).

**Оценка:** 2–3 сессии. Зависимости: утверждение D-001, D-009.

- [ ] Логи не содержат секретов (проверка `grep` по выводу в тестовом запросе).

## Этап 4 — Авторизация и каркас админки ⬜

**Результат:** `admin_users` (сид из env/скрипта), argon2id, серверные сессии, `POST /login`, `POST /logout`, `GET /me`, rate limit, CSRF-заголовок, guard на `/api/v1/admin/*`, `/admin` layout (логин, дашборд-заглушка, навигация админки, мобильный вид), тесты Vitest на сервис сессий.

**Критерии готовности:**

- [ ] Неверный пароль → 401 + одинаковое сообщение и тайминг (нет user enumeration).
- [ ] 6 неудачных попыток за 15 минут → 429 и запись в лог/уведомление.
- [ ] Cookie: `HttpOnly`, `Secure` (в production), `SameSite=Lax`, срок 7 дней, ротация при входе.
- [ ] Logout инвалидирует сессию в БД.
- [ ] Прямой запрос к `/api/v1/admin/projects` без сессии → 401.
- [ ] Админка пригодна на 360 px (создание записи — одним пальцем).

**Оценка:** 2 сессии. Зависимости: D-005 (модель авторизации).

## Этап 5 — Медиа-конвейер ⬜

**Результат:** `POST /api/v1/admin/media` (multipart), валидация magic bytes, `sharp`-конвейер (варианты + форматы), вырезание EXIF, blurhash, `StorageAdapter` (`local`/`s3`), публичная раздача вариантов, компонент `ProgressiveImage`, защита от decompression bomb.

**Критерии готовности:**

- [ ] JPEG/PNG/WebP/AVIF принимаются; PDF/SVG/GIF/исполняемые — отклоняются с понятной ошибкой.
- [ ] Файл > 15 MB → 413; 20 001×20 000 → отказ (лимит пикселей).
- [ ] Для загруженного фото генерируются 6 ширин × 3 формата; в БД сохранён blurhash.
- [ ] EXIF (в т. ч. GPS) отсутствует в производных файлах (проверка `exiftool`/`sharp metadata`).
- [ ] Оригинал недоступен по публичному URL.
- [ ] Имя файла — хеш; попытка `../` в имени не даёт доступа вне каталога.

**Оценка:** 2–3 сессии. Зависимости: D-004 (хранилище).

**Критерии готовности:**

- [ ] Проект создаётся, публикуется и появляется в публичном API только в статусе `published`.
- [ ] Черновик недоступен по прямому slug (404).
- [ ] Смена slug создаёт 301-редирект (или фиксируется как задача, если редиректы на Этапе 10).
- [ ] Дубликат slug → 409 с понятным сообщением.
- [ ] Порядок вывода соответствует `sort_order`.
- [ ] Публичный DTO не содержит служебных полей (проверка на тесте ответа).

**Оценка:** 3 сессии.

**Результат:** мультизагрузка фото в админке (drag&drop, прогресс, ошибки), CRUD метаданных, категории фото, публичная masonry-сетка, фильтры, лайтбокс (свайп/клавиатура/фокус-трап), `srcset`/`sizes`, плейсхолдеры.

**Критерии готовности:**

- [ ] 20 фото загружаются за один проход, без падения на мобильном интернете.
- [ ] Публикация фото без `alt` запрещена.
- [ ] Сетка не вызывает CLS (проверка Layout Shifts в Lighthouse).
- [ ] Лайтбокс полностью управляется клавиатурой и свайпом; фокус возвращается на исходное фото.
- [ ] Первый экран галереи: ≤ 8 тяжёлых запросов.

**Оценка:** 2–3 сессии.
